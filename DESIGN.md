# DESIGN.md

Дизайн-система проекта. **Это источник правды.** Значения токенов в
`app/assets/css/tailwind.css` — производные от этого файла, не наоборот.

## Как этим пользоваться

1. Правите этот файл: цвета, шрифты, правила по компонентам.
2. Просите агента: «приведи проект в соответствие с DESIGN.md».
3. Агент переписывает блоки `:root` / `.dark` в `app/assets/css/tailwind.css`
   и, где нужно, классы компонентов.
4. `npm run design:check` проверяет, что CSS не разъехался с этим файлом.

Формат токенов ниже — CSS custom properties, а не YAML/DTCG из черновой
спецификации Google. Так значения совпадают с CSS один в один и проверяются
автоматически. Если понадобится совместимость с официальным CLI — блок
конвертируется скриптом.

### Правила использования

<!-- ЗАПОЛНИТЬ под проект -->

- `primary` — только для главного действия на экране, не больше одного.
- `destructive` — необратимые действия. Не для валидационных ошибок формы.
- `muted-foreground` — вторичный текст, подписи, плейсхолдеры.
- `accent` — состояния наведения и выделения, не для залитых кнопок.

## 8. Доступность

- Контраст текста к фону — не ниже WCAG AA (4.5:1 для основного текста).
- Иконочные кнопки обязаны иметь `aria-label`.
- Интерактивные элементы достижимы с клавиатуры, фокус виден.

## 9. Чего не делать

<!-- ЗАПОЛНИТЬ под проект -->

- Не писать цвета хексами в шаблонах — только через слоты выше.
- Не использовать утилиты, удалённые в Tailwind 4 (`max-w-screen-*`,
  `flex-shrink-*`, `*-opacity-*`): они не выдают ошибку, просто не работают.
